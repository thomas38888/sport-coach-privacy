Données conservées sur votre appareil

Sport Coach permet de planifier et suivre les entraînements, les performances, la récupération, les habitudes et les informations de santé que vous saisissez.

Ces informations peuvent inclure votre nom, âge, sexe, mensurations, objectifs, blessures et restrictions, séances, douleurs, fatigue, sommeil, alimentation, allergies, intolérances, notes et activités GPS.

Le profil, les journaux et l’historique sont conservés dans le stockage local de l’appareil. Ces données ne sont pas envoyées à notre serveur du seul fait d’utiliser les fonctions locales. Le stockage local complet n’est pas présenté comme une base chiffrée ; protégez votre appareil. Les sauvegardes système Android de cette application sont désactivées dans la configuration de diffusion.

Les données locales restent sur votre appareil jusqu’à leur suppression dans l’application ou par vos actions sur l’appareil.

IA distante optionnelle

La génération distante est envisagée pour les adultes invités, après validation du service et des informations de confidentialité. Son utilisation nécessite un code individuel de test, un profil indiquant 18 ans ou plus, votre confirmation de majorité et votre accord explicite aux données personnelles et de santé dans l’écran Confidentialité. Vous pouvez continuer à utiliser les programmes locaux sans activer cette option.

Informations transmises et finalité

Lors d’une génération ou adaptation distante, le profil d’entraînement et le contexte IA sont transmis au serveur Sport Coach hébergé chez Supabase, puis à OpenAI lorsque le fournisseur est activé, pour personnaliser le programme.

Le contexte peut inclure âge, sexe, mensurations, objectifs, équipements, disponibilités, blessures, restrictions, récupération, alimentation, allergies et intolérances, ainsi que le programme courant, les séances réalisées, les performances et les retours de douleur, fatigue, sommeil et commentaires. Le champ nom du profil, les identifiants locaux, les champs non prévus et les parcours GPS sont exclus du contexte envoyé. Les notes et autres textes libres peuvent néanmoins identifier une personne ; n’y inscrivez pas de noms ni de données concernant d’autres personnes. Cette minimisation ne rend pas les informations anonymes.

L’envoi utilise une connexion HTTPS. Une génération locale reste disponible sans cet accord, ainsi qu’en cas d’indisponibilité du service distant. Si le fournisseur IA est désactivé côté serveur, le contexte d’une demande distante consentie traverse Supabase, mais n’est pas envoyé à OpenAI ; la réponse est alors un programme de repli.

Traitement et conservation

Le service ne crée pas de compte utilisateur Supabase et ne synchronise pas votre profil ou votre historique dans une base distante. La fonction serveur traite le contexte reçu en mémoire ; la base privée dédiée contient les accès de test et les compteurs de protection contre les abus. Cela ne supprime pas le traitement d’informations de santé par Supabase, puis OpenAI lorsque le fournisseur est activé, lors d’une demande distante.

La configuration demande à OpenAI de ne pas conserver la réponse comme un objet récupérable. Les options de partage volontaire de données sont désactivées. Selon la documentation OpenAI, les données de l’API ne servent pas à entraîner les modèles par défaut, sauf participation volontaire. Les journaux de surveillance des abus peuvent néanmoins contenir les demandes et réponses et être conservés jusqu’à 30 jours, avec des exceptions notamment légales. Aucune option de conservation nulle approuvée n’est vérifiée ici.

Lieu de traitement et transferts

La base Supabase est située en Irlande, dans l’Union européenne. Cette région ne garantit pas que l’exécution des fonctions serveur, le support ou toutes les opérations de l’hébergeur ont lieu au même endroit. Un essai avec des données fictives a notamment été exécuté à Zurich, en Suisse ; cela ne fixe pas le pays des demandes futures. Le projet API OpenAI utilise une résidence « Global », qui ne garantit pas un traitement exclusivement dans l’Union européenne.

Les conditions Supabase incorporent son accord de traitement des données, qui décrit les données de santé et prévoit les clauses contractuelles types pour les transferts concernés. Les opérations de support ou de service peuvent impliquer notamment Singapour et les États-Unis, selon la documentation sur les transferts et la liste de sous-traitants. Ces garanties ne rendent pas tous les traitements européens ; leurs informations peuvent être demandées au responsable.

Les informations sur certains journaux et copies décrits ci-dessous restent à préciser, ainsi que la couverture de l’envoi volontaire de santé à OpenAI avant son activation avec des données réelles. L’option distante reste fermée aux testeurs pendant cette préparation.

Votre consentement et sa preuve locale

La base proposée pour cette option est votre consentement à la personnalisation distante, avec accord explicite aux données de santé, selon les articles 6.1.a et 9.2.a du RGPD. Le refus conserve les fonctions locales. Les précisions de fournisseurs indiquées dans cette page restent à obtenir avant l’ouverture concernée.

La preuve de votre choix est enregistrée sur cet appareil dans le stockage sécurisé : version et URL de la politique, texte accepté, date UTC et confirmations de majorité et de santé. Elle ne contient ni code de test ni profil de santé, et n’est pas envoyée au serveur ou exportée dans la sauvegarde. Un ancien accord ou une version/URL différente n’autorise pas l’envoi. Après import d’une sauvegarde, un nouvel accord est demandé.

Retirer votre accord

Vous pouvez retirer votre accord et supprimer le code de test depuis Confidentialité. Cela empêche les futurs envois et les demandes encore en attente des lectures locales de l’accès ; un traitement déjà commencé ou terminé ne peut pas être annulé par cette action. Le reçu et le code sont effacés si le stockage accepte l’opération. Un échec est signalé et ferme l’accès pour la session courante ; refaire le retrait après réouverture plutôt que supposer l’effacement persistant. Pour les données déjà transmises, contactez le responsable. Les clés des fournisseurs restent exclusivement côté serveur.

Position et activités GPS

L’accès à la position est demandé au démarrage d’un enregistrement GPS. Vous pouvez refuser ou modifier cette autorisation dans les réglages Android. Le parcours actuel utilise la localisation au premier plan et ne demande pas de localisation en arrière-plan.

Le suivi calcule la distance et conserve les points GPS et les activités dans l’historique local, sauf export effectué par vous. Les écrans actuels ne présentent pas de fond de carte Google Maps.

Une dépendance native Maps reste présente pour compatibilité. La présence effective des composants natifs et leurs éventuels flux, ainsi que ceux des services de localisation du téléphone, doivent être vérifiés sur le binaire distribué. L’absence d’affichage d’une carte ne permet pas d’affirmer l’absence de toute communication du système ou d’un SDK.

Accès de test, sécurité et conservation

Le code individuel est conservé dans le stockage sécurisé de l’appareil natif. La base privée Supabase conserve une empreinte du code autorisé et des compteurs par accès et pour l’ensemble du test, afin de limiter les abus. Elle ne contient pas le profil de santé ni l’historique sportif.

Des limites par minute, par jour et de demandes simultanées protègent le service. La fermeture d’un accès bloque les nouvelles admissions ; elle n’annule pas une demande déjà admise ni un traitement déjà commencé chez OpenAI.

Durée des accès fermés

Le responsable a choisi, le 12 octobre 2026, de supprimer les empreintes d’accès et leurs compteurs associés au plus tard 30 jours après la fermeture de l’accès, en fonctionnement normal. Les codes encore ouverts doivent être fermés par le responsable à la fin du test.

Nettoyage quotidien — premier passage réussi

La purge quotidienne est installée et programmée à 03 h 15 UTC. Son premier statut automatique réussi a été vérifié le 13 octobre 2026 ; le nombre supprimé n’a pas été lu. En fonctionnement normal, elle supprime les accès fermés et leurs compteurs associés entre 29 et 30 jours après fermeture. Une pause de l’hébergement gratuit ou un incident peut retarder cette exécution ; la reprise, le contrôle de suppression et le suivi des retards restent nécessaires.

Les anciennes lignes de compteurs opérationnels sont également supprimées lors des appels ultérieurs après expiration de leur période utile. L’expiration seule d’un compteur ou d’une réservation ne prouve pas son effacement immédiat lorsqu’aucun appel ultérieur ne déclenche cette suppression.

Journaux, copies et accès administratifs

Le code serveur déployé ne journalise ni le corps des demandes, ni les codes d’accès, ni le texte des messages d’erreur du fournisseur IA. L’hébergeur traite toutefois des événements et métadonnées réseau : adresse IP, localisation approximative déduite de l’IP, informations de navigateur, empreintes de connexion, préfixe d’authentification tronqué, dates, statut, durée et tailles. Ces catégories ont été observées sur un essai fictif ; elles sont distinctes des parcours GPS exclus du contexte envoyé par l’application. Aucun champ de corps n’a été observé dans cet enregistrement précis. Sa documentation des traces Edge décrit aussi des corps de requête/réponse dans Invocations : leur capture reste possible dans les autres traces ou copies malgré l’absence de journalisation dans notre code, et doit être précisée avant ouverture.

L’offre Supabase gratuite annonce un jour de conservation pour les journaux API et base. Cette durée ne prouve pas une rétention unique de toutes les traces, journaux de fonctions, exports ou copies.

Les sauvegardes quotidiennes accessibles ne sont pas incluses dans notre projet Free. La restauration d’un projet pausé est possible pendant un an ; cela ne donne pas un maximum général d’effacement de toutes les copies internes. La suppression des lignes de la base ne prouve pas leur disparition physique immédiate des instantanés.

Selon les critères publiés par Supabase, les données de base sont conservées tant que le projet est actif et les données client sont supprimées dans les trente jours suivant la suppression du projet. Son accord de traitement prévoit aussi l’effacement des copies après la période de trente jours suivant l’expiration du contrat. Ces événements sont distincts de la révocation d’un code ou de la suppression d’une ligne ; ils ne donnent pas une durée spécifique pour chaque journal opérationnel ou de sécurité.

Thomas DURON est le seul administrateur de l’organisation Supabase observé le 12 octobre 2026. Les personnels autorisés des fournisseurs et leurs sous-traitants peuvent intervenir pour les besoins du service selon leurs garanties contractuelles. La purge des accès ne nettoie pas les journaux Cron ou les traces de plateforme.

Export, import et effacement

Vous pouvez exporter une sauvegarde JSON depuis Confidentialité et la partager vers la destination de votre choix. L’application garde cet export dans son propre dossier de sauvegardes. Ce fichier peut contenir des données sensibles : la destination partagée et la conservation de cette copie externe relèvent de votre décision. Un import confirmé remplace les données locales et désactive l’accord IA, en conservant le code pour une nouvelle activation.

La copie d’import reconnue dans le cache de l’application est effacée après succès, refus ou erreur, avec avertissement en cas d’échec. Le fichier source situé ailleurs reste conservé.

L’effacement confirmé supprime les données de l’application, les accès et accords sécurisés, ses exports et copies d’import reconnus dans ses dossiers propres. Les fichiers inconnus sont conservés par précaution et signalés ; un échec est annoncé comme suppression incomplète. Les fichiers source, copies partagées ailleurs et informations déjà traitées par un destinataire externe restent à traiter séparément. Contactez-nous pour les traitements côté serveur ou fournisseur.
